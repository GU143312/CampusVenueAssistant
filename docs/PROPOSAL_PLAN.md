## 还需要什么

1. API与模型：在本机安全配置API Key，选取账户可用模型，锁定model ID及费用预算；先做一条最小调用。没有Key也能演示现有表单/MCP链路。
2. 自然语言控制器：用结构化schema提取需求；明确区分缺失与不限；缺少日期、时间边界、人数、时长和设备要求时追问。日期有歧义先确认。保存每会话需求版本，修改人数后不能复用旧候选。
3. 只读Agent协作：Coordinator负责对话，Search负责查规则与空位。接入Search.as_tool；验证JSON边界。候选由控制器复核后渲染，不能直接信任模型编造的房间/时间。Execution留到预约阶段。
4. 评估：先准备12条只读开发案例；对完整自然语言系统各跑3次。至少覆盖正常、偏好/必须、缺字段、歧义日期、更新人数、无解、资格、工具失败和注入文本。目标≥90%仅为计划阈值，当前没有LLM成功率数据。
5. 演示保障：按README在另一台机器安装一次；保存依赖锁与数据快照；完成2分钟演示录像作为断网备份。准备PPT/PDF拷贝与每人讲稿。
